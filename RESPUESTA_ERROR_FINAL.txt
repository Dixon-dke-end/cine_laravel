🔴 ERROR QUE TENÍAS:

   "me lanza error al procesar la reserva"
   
   Error exacto: Auth guard [sanctum] is not defined
   Cuándo: Al presionar CONTINUAR en página de sillas
   Dónde: POST /api/reservas

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔧 SOLUCIÓN APLICADA:

   Cambio 1: Agregué guard 'sanctum' a config/auth.php
   ────────
   Archivo: config/auth.php (alrededor de línea 45)
   Agregué:
   
   'sanctum' => [
       'driver' => 'sanctum',
       'provider' => 'users',
   ],

   Cambio 2: Cambié auth:sanctum a auth:web en routes/api.php
   ────────
   Archivo: routes/api.php (alrededor de línea 35)
   
   ANTES: Route::middleware('auth:sanctum')->group(...)
   AHORA: Route::middleware('auth:web')->group(...)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔍 POR QUÉ FUNCIONABA INCORRECTAMENTE:

   1. config/auth.php no tenía guard 'sanctum' configurado
      └─ Routes intentaban usar un guard que no existía
      
   2. Usabas autenticación de SESIÓN WEB (navegador)
      └─ No autenticación de SANCTUM (tokens API)
      
   3. Mismatch: Las rutas esperaban Sanctum pero enviabas web
      └─ Sistema rechazaba la autenticación

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ AHORA FUNCIONA:

   Flujo correcto:
   
   1. Usuario hace login (crea sesión web)
   2. Frontend POST /api/reservas (con cookies de sesión)
   3. Middleware auth:web verifica sesión
   4. ✅ Usuario autenticado
   5. Backend crea reserva en BD
   6. Response: {"success": true}
   7. Frontend redirige a /mis-reservas
   8. ✅ ÉXITO
